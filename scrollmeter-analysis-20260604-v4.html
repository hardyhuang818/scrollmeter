① A vs C — 排除"DisplayLink 后台负载量有罪"
Rules out background-load hypothesis

A 和 C 都有 2 路 DisplayLink 同时软编码，CPU 负担相同。唯一区别：A 滚动跑在原生内置屏，C 滚动跑在 DisplayLink 路径上。结果：A 0 hitch，C 10–12 ms/s。
A and C both run 2 concurrent DisplayLink software encoders (identical CPU burden). Only difference: A scrolls on the native built-in screen; C scrolls via DisplayLink. A → 0 hitch, C → 10–12 ms/s. Rules out "DisplayLink stream count causes jank".

② B vs C — 排除"显示器本身有问题"
Rules out monitor hypothesis

B 和 C 滚动目标是同一台物理 ASUS PG27 4K60，相同内容、相同触控板、相同 3 块活跃屏。唯一区别：cable 路径——B 走内置 HDMI（硬件视频引擎），C 走 DisplayLink（USB 软编码）。结果：B 0 hitch，C 10–12 ms/s。
B and C scroll on the same physical ASUS PG27 4K60 with the same content, trackpad, and 3 active displays. Only the cable path differs — built-in HDMI (hardware video engine) for B, DisplayLink (USB software encoder) for C. B → 0 hitch, C → 10–12 ms/s. Rules out "the monitor itself is at fault".

③ D 正面对照 — 排除"4K 分辨率太高 / 外接屏数量太多"
Positive control — rules out resolution & display-count hypotheses

D 组合盖 Clamshell，同时驱动 2 块 4K 60Hz 外接屏，但走 HBP Hub 的 Thunderbolt 硬件视频桥接（与内置 HDMI 同级），完全不经过 DisplayLink。结果：Hitch = 0，FPS 稳定 60.0。这把可能剩下的两个备选解释也排除了：
D drove 2× 4K 60Hz external displays simultaneously via HBP Hub's Thunderbolt hardware video bridge (same tier as built-in HDMI), with no DisplayLink involved. Result: 0 hitch, steady 60.0 fps. This rules out the two remaining alternative hypotheses:

  • ❌ "4K 60Hz 这种规格的外接屏天生卡" / "4K 60Hz resolution is inherently too much" — D 同时推 2 块 4K 60Hz 仍 0 hitch
  • ❌ "外接屏数量太多 macOS 处理不过来" / "macOS struggles with multiple external displays" — D 推 2 块外接屏仍 0 hitch

结合三组对照（A vs C 控制 DL 负载、B vs C 控制监视器、D 正面控制 4K/数量），所有干扰因素都被剥干净，只剩一个变量：
滚动渲染目标的传输路径是否经过 DisplayLink。 DisplayLink 的 USB 软编码链路是滚动卡顿的唯一原因，与负载、监视器、分辨率、外接屏数量均无关。
Combining the three controls — A vs C (DL load), B vs C (monitor), D (4K/count positive control) — every confound is stripped. Only one variable remains: whether the scroll rendering target's transport path goes through DisplayLink. DisplayLink's USB software encoding is the sole cause of jank, independent of load, monitor, resolution, or display count.
