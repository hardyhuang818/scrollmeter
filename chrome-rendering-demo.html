这不是真实测试 / This is NOT a real benchmark — 它是一个单线程 JS 示意动画，左右两侧用同一段 rAF 驱动；之所以能看出差异，是因为我们 人为模拟 了"主线程被 JS 占住"这一事件，并让左侧（软件路径）滚动跟着停，右侧（GPU 路径） 继续走。

怎么读这个 demo / How to read it:
  • 🔥 滑杆 = 模拟"持续 CPU 压力"。默认 30%，左边软件路径已经看得到掉帧、FPS 下降，右边 GPU 路径 60 不动。
  • 把滑杆拉到 60%+，左边滚动开始明显卡顿，右边继续顺滑——这就是 GPU 加速的真实价值。
  • ⚡ 按钮 = 一次性 500ms JS 阻塞峰值。左边整窗冻住、右边照常走。
  • 红色"Frames missed"计数差距、左边时间轴上的橙色 JS 块，就是关键信号。
想做真实测试 / For real measurement: 用本仓库的 run-bench.command， 然后一边滚动一边在另一个终端跑 yes > /dev/null & yes > /dev/null & (Ctrl-C 终止) 给系统加 CPU 压力, 对比 hitch ratio 的变化。
